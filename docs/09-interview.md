# 면접에서 설명하기

## 프로젝트 소개

“본사와 지사 사이의 통신 환경을 구성하고, 주요 장비와 경로를 이중화한 프로젝트입니다. 본사 내부는 VLAN과 STP, HSRP로 구성했고, 지사는 VPN으로 연결했습니다. 설정을 넣는 데서 끝내지 않고 코어와 터널을 내려서 역할과 경로가 바뀌는지도 확인했습니다.”

## 왜 Rapid PVST+를 썼나요?

“VLAN마다 Root를 다르게 지정하고 빠른 경로 전환을 확인하고 싶어서 사용했습니다. VLAN이 다섯 개 정도라 각각 관리해도 부담이 크지 않았습니다. VLAN이 훨씬 많아지는 환경이라면 여러 VLAN을 묶는 MST도 검토하겠습니다.”

## 왜 HSRP이고 VRRP나 GLBP는 아니었나요?

“Cisco 기반 실습에서 VLAN별 Active와 장애 시 우선순위 변화를 확인하는 데 HSRP가 맞았습니다. 같은 VLAN 안의 단말을 여러 게이트웨이에 분산하는 것보다 VLAN별 역할을 명확하게 나누는 구성이 목적이었습니다. 제조사가 섞이는 환경이라면 VRRP를 검토할 수 있습니다.”

## STP와 HSRP를 왜 같이 쓰나요?

“STP는 중복 연결의 L2 루프를 막고, HSRP는 기본 게이트웨이 장애에 대비합니다. 역할이 달라서 둘을 함께 썼고, VLAN별 Root와 Active 위치를 맞추는 방향으로 구성했습니다.”

## Track에서 OR를 사용한 이유는요?

“상위 링크 두 개 중 하나라도 살아 있으면 코어를 사용할 수 있다는 조건으로 묶었습니다. 둘 다 내려갔을 때만 묶음이 Down이 돼 우선순위를 낮추는 구성입니다. 다만 상대가 역할을 가져오려면 Preempt 조건도 맞아야 해서 코어 전원 장애와는 나눠 시험해야 합니다.”

## 재분배 루프는 어떻게 막았나요?

“다른 프로토콜로 넘길 때 태그를 붙이고, 그 태그를 가진 경로가 다시 돌아올 때 필터링하는 방식을 사용했습니다. AD 조정은 선호 경로를 바꾸는 것이고 루프 방지를 단독으로 보장하지는 않습니다.”

## DMVPN Phase 2와 3의 차이는요?

“둘 다 스포크 간 직접 통신을 지원합니다. Phase 3는 허브의 Redirect와 스포크의 Shortcut으로 더 짧은 전달 경로를 학습합니다. 저희 보관본에는 Phase 표기와 next-hop 설정이 일반 설명과 다른 부분이 있어, 해당 실습의 관찰 결과와 프로토콜 일반론을 구분해서 설명하겠습니다.”

## 무엇을 검증했고 한계는 무엇인가요?

“기존 발표 자료에는 코어 장애 후 역할 변경, 엣지 우회, 주 터널 중단 후 백업 경로와 복귀를 기록했습니다. 정확한 전환 시간이나 패킷 손실률을 측정한 자료는 없어서 무중단이라고 말하지는 않겠습니다. 남은 설정 차이는 별도로 정리했고 다시 구성한다면 원시 출력부터 수집하겠습니다.”

## 본인 역할은요?

팀 전체 성과를 그대로 개인 성과로 답하지 않습니다. 실제 담당 장비, 직접 작성한 설정, 직접 시험한 구간과 협업한 범위를 구체적으로 정리한 후 답합니다. 이 문서에서는 개인별 역할을 임의 배정하지 않았습니다.
