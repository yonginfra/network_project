# 프로젝트 개요

본사-지사 통합 네트워크 구축 및 이중화 인프라 설계

본사 내부망, 지사망, 인터넷 역할의 ISP망을 연결하고 장비·링크·터널 장애 상황에서 통신 경로가 바뀌는지 확인한 네트워크 실습 프로젝트입니다.

| 항목 | 내용 |
| --- | --- |
| 기간 | 2026.06 - 2026.07 (이력서 기재 기준) |
| 팀 | 송용·남기석 |
| 환경 | Cisco IOS 기반 실습, GNS3·콘솔 접속 환경 |
| Topology 1 | 본사 코어 2대·엣지 2대·액세스 4대, 지사 4곳, 이중 허브 DMVPN |
| Topology 2 | 본사 코어·엣지 이중화, 지사 2곳, GRE over IPsec 주·백업 터널 |
| 이번 정리 | 원본 설정 파일과 43장 발표 자료를 교차 확인한 문서화 작업 |

## 어떤 문제를 해결하려 했나

게이트웨이와 상위 연결이 하나뿐이면 한 지점의 장애로 통신이 끊길 수 있습니다. 본사 내부에는 중복 연결을 두되 L2 루프를 막고, 외부 연결과 VPN에는 대체 경로를 구성했습니다. 이때 이중화는 장비를 두 대 두는 것만이 아니라, 장애 감지·경로 선택·복구 후 역할까지 연결하는 작업으로 다뤘습니다.

## 진행 흐름

요구사항·토폴로지 → VLAN·Trunk·VTP → LACP·Rapid PVST+ → SVI·HSRP·Track → OSPF·EIGRP → VPN·재분배 → NAT/PAT → 장애·복귀 확인

## 핵심 결과

- VLAN별로 STP Root와 HSRP Active를 나눠 내부 경로를 구성했습니다.
- 발표 자료에 코어 중단·복구 후 HSRP 역할 전환과 엣지 장애 시 우회 경로를 남겼습니다.
- DMVPN 구성과 GRE over IPsec 구성을 분리해 연결 방식과 경로 전환을 확인했습니다.
- 재분배 경로에 태그와 필터를 적용하고 라우팅 테이블을 확인했습니다.

결과는 당시 발표 자료의 기록입니다. 이번 문서화에서 장비를 실행하거나 장애 시험을 다시 하지는 않았습니다. 원본 설정과 발표 설명이 다른 부분은 [확인·보완 사항](07-findings.md)에 구분했습니다. 장애 전환 시간·패킷 손실률·처리량을 새 수치로 만들지 않았습니다.

## 팀 작업과 개인 역할

설명은 팀 전체 구성과 결과 기준입니다. 자료만으로 개인별 담당 장비와 설정 범위를 확정하지 않았습니다. 이력서의 본인 역할은 직접 수행한 장비 구성·시험 범위를 기준으로 별도로 작성합니다.
