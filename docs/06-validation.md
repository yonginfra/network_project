# 장애 전환과 검증 기록

## 기록의 기준

아래 '기존 기록'은 팀 발표 자료에 남은 설명과 캡처가 기준입니다. 이번 문서 작성 중 장비를 실행하지 않았습니다. 원본 설정 정적 확인, 과거 실습 결과, 향후 재시험 항목을 구분합니다.

| 시험 | 기존 발표 자료 | 확인한 범위 | 현재 해석 |
| --- | --- | --- | --- |
| STP Root 분담 | 슬라이드 10 | Core 장애 시 Root 변화 설명 | VLAN별 Root 재확인 필요. Root Cost 0만으로 전체 장애 복구를 판정하지 않음 |
| HSRP 코어 중단·복귀 | 슬라이드 13~14 | Core1 Down 시 Core2 Active, 복구 후 역할 복귀 | 전원 장애 시나리오. Track만의 성공 증거와 구분 |
| VLAN별 엣지 경로 | 슬라이드 15 | VLAN별 Traceroute 경로 | 특정 단말·목적지의 관찰 결과 |
| Edge1 장애 우회 | 슬라이드 16 | 다른 엣지를 거치는 경로 설명 | HSRP 역할 전환과 OSPF 우회를 별도로 관찰 |

| 재분배 경로 | 슬라이드 33~40 | D EX·O E2 경로와 태그 정책 설명 | 모든 경로의 루프 제로를 증명한 것은 아님 |
| NAT | 슬라이드 41 | 장비별 Inside/Outside 및 인터넷 통신 설명 | NAT 설정과 통신 확인 범위로 기술 |

## 재시험 순서

1. 정상 상태에서 VLAN별 Root·HSRP 역할, 라우팅 테이블과 VPN 등록·SA를 저장합니다.
2. 한 번에 한 장애만 만듭니다. 코어 중단, 업링크 하나 중단, 업링크 둘 중단은 서로 다른 시험입니다.
3. 연속 Ping을 유지하고 상태·다음 홉·포트 변화를 기록합니다.
4. 복구 후 Preempt 지연과 경로 복귀를 확인합니다.
5. 시작·장애·복구 시각과 실패 패킷을 남긴 경우에만 전환시간이나 손실을 수치로 적습니다.

## HSRP Track 시험에서 구분할 것

Topology 1은 업링크 두 개를 OR로 묶었습니다. 한쪽만 내려도 무조건 Track Down이 되는 구성이 아닙니다. 두 링크 모두 Down일 때 우선순위가 내려가며, 상대 Preempt 설정에 따라 Active 전환 결과가 달라질 수 있습니다. 코어 전원을 끈 시험 결과를 이 시험의 성공으로 대신하지 않습니다.
